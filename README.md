# هم‌قدم

**قبل از رفتن، مطمئن شو.**

دستیار خرید حضوری برای فروشگاه‌های تهران. کاربر می‌گوید چه می‌خواهد؛ هم‌قدم محصول را از دیتاست ترب پیدا می‌کند، فروشگاه‌های نزدیک را مقایسه می‌کند، از فروشنده می‌پرسد که واقعاً موجود است یا نه، و یک برنامه‌ی سفر با جایگزین و چک‌لیست می‌سازد.

## چرا

قیمت ثبت‌شده با موجودی یکی نیست. یک آفر یعنی فروشگاه قیمت داده؛ نه اینکه کالا روی قفسه است. هم‌قدم این دو را جدا نگه می‌دارد:

- **قیمت:** «ثبت‌شده ۹ روز پیش» یا «تأیید فروشنده ۱۴:۳۲»
- **موجودی:** «نامشخص» تا وقتی فروشنده تأیید کند
- **ساعت:** «اعلام‌شده»، «الان باز است» یا «نامشخص»
- **پرداخت:** فقط گزینه‌های اعلام‌شده؛ نبودِ اطلاعات یعنی نامشخص

## اجرا

```bash
# 1. دیتابیس را از CSVها بساز (یک‌بار)
python3 scripts/build_db.py

# 2. وابستگی‌ها
npm install

# 3. کلید DeepSeek را در .env.local بگذار
cp .env.example .env.local
# DEEPSEEK_API_KEY=...

npm run dev
```

`http://localhost:3000`

## دمو

1. صفحه اصلی → «دموی آماده» → «فروشگاه‌ها را پیدا کن»
2. کارت‌ها را ببین؛ «قیمت ثبت‌شده» و «موجودی نامشخص» را از هم جدا بخوان
3. «ویرایش درخواست» → دسته را به «ساعت» عوض کن؛ بودجه و محدوده می‌مانند
4. «از ۳ فروشگاه بپرس»
5. در تب دیگر `/store` → فروشگاه → پاسخ آزاد بنویس:
   - «این مدل ۲۵۶ تموم شده.» → دستیار جایگزین می‌آورد و فروشگاه بعدی را می‌پرسد
   - «هست ۱۸۴٬۶۰۰٬۰۰۰ تومان. تا ۹ شب. گارانتی ۱۸ ماه.» → کارت تأیید می‌شود
6. «برنامه سفر» → فروشگاه اصلی، جایگزین، مسیر و چک‌لیست

برای شروع تازه: دکمه‌ی «بازنشانی» در پنل فروشنده یا `POST /api/demo/reset`.

## فنی

- Next.js 16 + TypeScript + Tailwind v4
- SQLite + FTS5 (۲۲۵٬۹۰۳ محصول، ۳۳۱٬۵۰۶ آفر)
- DeepSeek برای تحلیل نیت و خواندن پاسخ فروشنده؛ fallback قاعده‌محور
- Leaflet + OpenStreetMap
- حلقه‌ی عامل: انتخاب ۳ فروشگاه → پیام → خواندن پاسخ → پیگیری → جایگزین → برنامه سفر
- بدون لاگین، بدون پرداخت واقعی؛ پنل فروشنده نسخه‌ی نمایشی است

## داده

منبع: `torob-dataset/` (خروجی چالش ترب). ۶٬۴۷۶ فروشگاه، ۲۲۵٬۹۰۳ محصول، ۳۳۱٬۵۰۶ آفر. نام ۶٬۳۶۴ فروشگاه و شماره‌ی همه‌ی فروشگاه‌ها نمایشی است؛ شماره‌ی جعلی را دکمه‌ی تماس نمی‌کنیم. صفحه‌ی `/data` این محدودیت‌ها را نشان می‌دهد.
